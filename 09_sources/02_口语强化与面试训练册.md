**训练原则：先开口，再纠错；先讲清楚，再追求高级表达。**

# 训练规则：每一个句子做四轮

1.  第 1 轮 · 跟读：看英文朗读，按意群停顿，不追求语速。

2.  第 2 轮 · 遮挡：先看中文，尝试说出英文；说不出时看关键词，不马上看整句。

3.  第 3 轮 · 替换：把技术名词、问题、方案和结果替换成自己项目里的内容。

4.  第 4 轮 · 录音：脱稿讲 30–90 秒，回听并标记停顿过长、用词不准和逻辑跳跃。

每次只纠正 2–3 个问题。不要一边说一边追求每个冠词都完美，否则会失去表达流畅度。

# 练习 C · 中文转英文（先做题，再看答案）

1\. 我的主要工作是编排多个工具，完成一个端到端的音乐生成流程。

2\. 我会先验证输入，再调用模型或外部工具。

3\. 如果工具调用失败，我们需要区分临时错误和不可恢复的错误。

4\. 我们使用混合检索提高专业术语的召回效果。

5\. 最终答案的质量不仅取决于模型，也取决于检索结果。

6\. 我会在代表性测试集上验证这个改动，而不是只依靠主观判断。

7\. 这个方案降低了延迟，但增加了缓存失效处理的复杂性。

8\. 我还没有在生产环境中使用过这个工具，所以我不想夸大自己的经验。

9\. 我们需要在准确率、延迟、成本和可维护性之间做权衡。

10\. 我会先定位瓶颈，再决定是否需要优化算法、数据库或模型服务。

11\. 检索内容和工具输出应被视为不可信输入。

12\. 我负责把底层告警归并成更高层的攻击意图。

13\. 我们保留了人工审核环节，以控制高影响决策的风险。

14\. 我先确认预期行为和验收标准，再讨论实现方案。

15\. 如果这个假设不成立，我会重新评估架构。

16\. 目前还不能确定根因；我正在检查日志、指标和最近的部署。

17\. 我会保存工作流状态，以便任务中断后可以恢复。

18\. 我们需要评估音频质量、音乐连贯性和用户偏好。

19\. 这个改动可能引入竞态条件，因此需要增加并发测试。

20\. 我会把已知事实和自己的假设分开说明。

# 练习 C · 参考答案

**1.** My main responsibility is to orchestrate multiple tools into an end-to-end music generation workflow.

**2.** I validate the input before calling a model or an external tool.

**3.** If a tool call fails, we need to distinguish transient errors from non-recoverable errors.

**4.** We use hybrid search to improve retrieval for domain-specific terminology.

**5.** The quality of the final answer depends not only on the model but also on the retrieved evidence.

**6.** I would validate this change on a representative test set rather than relying only on subjective judgment.

**7.** This approach reduced latency but added complexity around cache invalidation.

**8.** I haven’t used this tool in production, so I don’t want to overstate my experience.

**9.** We need to balance accuracy, latency, cost, and maintainability.

**10.** I would identify the bottleneck first, then decide whether to optimize the algorithm, database, or model serving.

**11.** Retrieved content and tool outputs should be treated as untrusted input.

**12.** I was responsible for correlating low-level alerts into higher-level attack intent.

**13.** We kept a human review step to control the risk of high-impact decisions.

**14.** I clarify the expected behavior and acceptance criteria before discussing the implementation.

**15.** If this assumption does not hold, I’ll reassess the architecture.

**16.** The root cause is not confirmed yet. I’m checking the logs, metrics, and recent deployments.

**17.** I would persist the workflow state so the task can resume after an interruption.

**18.** We need to evaluate audio quality, musical coherence, and user preference.

**19.** This change could introduce a race condition, so we need to add concurrency tests.

**20.** I’ll separate the facts we know from the assumptions I’m making.

# 练习 F · 角色扮演对话

## A · 需求不清楚

Interviewer: What should the agent do when a tool returns incomplete output?  
You: Before choosing a behavior, I’d clarify whether the output is recoverable and what the user expects. I’d validate the output, retry only if appropriate, and ask for user input or use a fallback when needed.

训练重点：锻炼澄清需求和说明失败路径。

## B · 质疑 RAG 指标

Interviewer: You claim more than 85% accuracy. How was that measured?  
You: I would define the evaluation set, explain what counted as a correct answer, and compare against a baseline. I’d also report retrieval metrics separately from final-answer quality.

训练重点：锻炼诚实说明指标口径；把方括号中的事实补充完整。

## C · PR 意见不一致

Colleague: I think we should retry every failed tool call.  
You: I understand the idea, but retrying every error can waste resources or duplicate side effects. I’d classify errors first and retry only transient failures when the operation is safe to repeat.

训练重点：锻炼礼貌反对、解释风险和提出改进方案。

## D · 线上模型变慢

Manager: Latency doubled after deployment. What will you do?  
You: I’ll compare the metrics before and after deployment, break down model latency from retrieval and tool latency, and check resource utilization and traffic patterns. If user impact is high, I’ll consider rollback while investigating the root cause.

训练重点：锻炼 incident communication。
